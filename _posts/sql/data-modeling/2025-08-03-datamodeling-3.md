## 1. 속성의 개념

- 속성은 <mark>업무에서 필요</mark>로 하는 인스턴스에서 관리하고자 하는 <mark>의미상 더이상 분리되지 않는 최소의 데이터 단위</mark>
    - 의미상 분리X → 생년월일은 하나로서 의미 연·월·일로 구분해서 저장한다면 관리 목적의 분리 → 기능점수(Function Point) 산정시, 하나의 속성(DET)으로 계산
    - 이름주소로 관련없는 속성으로 정의 → 값 의미의 속성보다는 내역(Description)
- 엔티티를 설명하는 <mark>인스턴스의 구성요소</mark>

---

## 2. 엔터티, 인스턴스와 속성, 속성 값에 대한 내용과 표기법

### 가. 엔터티, 인스턴스, 속성, 속성 값의 관계

- <mark>한 개의 엔터티는 두 개 이상의 인스턴스의 집합</mark>
    - ex. 엔티티 - 사원
- <mark>한 개의 엔터티는 두 개 이상의 속성을 가짐</mark>
    - ex. 사원 엔티티의 속성 - 이름, 주소, 전화번호, 직책
- <mark>한 개의 속성은 한 개의 속성 값(VALUE)을 가짐</mark>
    - 속성은 엔터티에 속한 엔터티에 대한 자세하고 구체적 정보
    - ex. 속성 값 - 홍길동, 강남구, 123, 대리

---

## 3. 속성의 특징

- 업무에 필요하고 관리하고자 하는 정보
- 정규화 이론에 근거하여 정해진 <mark>주식별자에 함수적 종속성</mark>을 가짐
- 하나의 속성은 한 개의 값만을 가짐
    - 다중 값은 별도의 엔터티를 이용하여 분리(1:N 관계로 표현)

---

## 4. 속성의 분류

### 가. 속성의 특성에 따른 분류

1. `기본 속성(Basic Attribute)`
    - 업무로부터 추출한 모든 속성
    - 일반적 속성, 수多
    - 다른 속성을 계산하거나 영향을 받아 생성된 속성을 제외한 모든 속성
    - 업무상 코드로 정의한 속성(F/M, 001/002 등)은 기본 속성X
2. `설계 속성(Designed Attribute)`
    - 데이터 모델링이나 업무를 규칙화하기 위해 속성을 새로 만들거나 변형하여 정의하는 속성
    - 코드성 속성은 대부분 변형하여 만든 설계 속성
        - ex. 일련번호, 성별코드
3. `파생 속성(Derived Attribute)`
    - 다른 속성에 영향을 받아 <mark>발생한 속성</mark> → 계산된 값
    - 프로세스 설계 시 데이터 정합성을 유지하기 위해 적게 정의하는 것이 권장
    - 통계 관련 엔터티나 배치 작업 수행하면서 발생하는 엔터티에 이용
    - 파생 속성의 계산 로직을 속성 정의서에 기록 후, 향후 속성 값 검증 시 활용
    - ex. 총 금액, 이자

### 나. 엔터티 구성방식에 따른 분류

1. `PK(Primary Key)속성`: 엔터티를 <mark>식별</mark>할 수 있는 속성 → 사원 번호
2. `FK(Foreign Key)속성`: 다른 엔터티와의 <mark>관계에서 포함</mark>된 속성 → 부서코드
3. `일반속성`: PK와 FK에 포함되지 않는 속성 → 사원명, 우편번호, 주소, 전화번호

### 다. 그 외 분류

- 세부 의미에 따른 분류
    1. 단순속성(Simple Attribute): 더 이상 다른 속성들로 구성X → 성별, 나이
    2. 복합속성(Composite Attribute): 여러 세부 속성들로 구성 → 주소(시, 구, 동, 번지)
- 속성 값 개수에 따른 분류
    1. 단일 값 속성(Single-Valued Atrribute): 하나의 값만 존재 → 주민번호
    2. 다중 값 속성(Multi-Valued Attribute): 여러 개의 값을 가짐 → 한 사람이 여러 전화번호를 가짐
        - 1차 정규화 또는 별도의 엔터티로 관계 연결

---

## 5. 도메인(Domain)

- <mark>도메인은 속성이 가질 수 있는 값의 범위</mark>
- 속성에 대한 데이터 타입과 크기, 제약사항을 지정
- <mark>속성은 도메인 이외의 값X</mark>
- ex. 학점 속성의 도메인은 0.0~4.0 사이의 실수 값, 주소 속성은 길이가 20자리 이내인 문자열

---

## 6. 속성의 명명

- 속성명이 사용자 인터페이스에 나타나기 때문에 도메인  정의를 하고 용어사전을 사용하여 정확히 부여
- 속성명 부여 원칙
    1. 해당 업무에서 사용하는 이름 부여
    2. 서술식 속성명X
        - 수식어, 소유격X
    3. 약어 사용X
    4. 전체 데이터 모델에서 유일성 확보
        - 반정규화 적용시 속성명의 충돌 방지
