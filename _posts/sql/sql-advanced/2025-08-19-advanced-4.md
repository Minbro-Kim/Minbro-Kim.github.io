## 1. 윈도우 함수 개요

- 행과 행간의 관계를 쉽게 정의하기 위해 만든 함수
- 분석함수(ANALYTIC FUNCTION) 또는 순위 함수(RANK FUNCTION)이라고 함
- 데이터 웨어하우스에서 발전한 기능
- 복잡한 튜닝 기법을 대체
- <mark>다른 함수와 달리 중첩(NEST)하여 사용 불가</mark>
    - 서브 쿼리에서는 가능
- 윈도우 함수 종류
    1. **그룹 내 순위(RANK) 관련 함수**
        - RANK, DENSE_RANK, ROW_NUMBER
        - 대부분의 DBMS 지원
    2. **그룹 내 집계(AGGREGATE) 관련 함수**
        - SUM, MAX, MIN, AVG, COUNT
        - 대부분 DBMS 지원
            - SQL Server는  OVER절 내의 ORDER BY구문 지원X
    3. **그룹 내 행 순서 관련 함수**
        - FIRST_VALUE,
    4. **그룹 내 비율 관련 함수**
        - CUM_DIST, PERCENT_RANK, NTILE, RATIO_TO_REPORT
        - CUM_DIST, PERCENT_RANK → ANSI/ISO SQL 표준 및 Oracle 지원
        - NTILE → ANSI/ISO SQL 표준X, Oracle 및 SQL Server 지원
        - RATIO_TO_REPORT → Oracle에서만 지원
    5. **선형 분석을 포함한 통게 분석 관련 함수**
        - 통계에 특화한 기능
        - CORR, COVAR_POP, COVAR _SAMP, STDDEV, VARIANCE 등
- WINDOW FUNCTION SYNTAX
    - **<mark>윈도우 함수에는 OVER 문구가 필수 포함</mark>**

    ```plsql
    SELECT WINDOW_FUNCTION (ARGUMENTS)
           OVER ([PARTITION BY칼럼][ORDER BY절][WINDOWING절])
    FROM 테이블명;
    ```

    - `WINDOW_FUNCTION`: 기존 집계 함수 또는 추가된 윈도우 함수
    - `ARGUMENTS(인수)`: 함수에 따라 0~N개의 인수 지정
    - `PARTITON BY` 절: 전체 집합을 기준에 의해 소그룹으로 나눔
    - `ORDER BY` 절: 어떤 항목에 대해 순위를 지정
    - `WINDOWING` 절: 함수의 대상이 되는 행 기준의 범위를 강력하게 지정
        - `ROWS`: 물리적인 결과 행의 수
        - `RANGE`: 논리적인 값에 의한 범위
        - SQL Server 지원X

## 2. 그룹 내 순위 함수

### 가. RANK 함수

- 특정 항목(칼럼)에 대한 순위를 구하는 함수
- 특정 범위(PARTITION) 또는 전체 데이터에  대한 순위를 구함
- <mark>ORDER BY절 필수 → 순위 기준</mark>
- <mark>동일한 값에 대해 동일한 순위 부여</mark> → ex. 1등 1등 3등

```plsql
SELECT PLAYER_NAME, TEAM_NAME, HEIGHT,
        RANK () OVER (ORDER BY HEIGHT DESC) AS "전체 키 순위",
        RANK () OVER (PARTITION BY TEAM_NAME ORDER BY HEIGHT DESC) AS "팀내 키 순위"
FROM 선수; 
```

### 나. DENSE_RANK 함수

- <mark>ORDER BY절 필수 → 순위 기준</mark>
- <mark>동일한 순위를 하나의 건수로 취급</mark> → ex. 1등 1등 2등

### 다. ROW_NUMBER 함수

- <mark>ORDER BY절 필수 → 순위 기준</mark>
- 동일한 값에 대해 고유한 순위 부여
- 데이터베이스별로 다른 결과 (Oracle은 rowid(행을 고유하게 식별하는 주소값)가 적은 행 먼저 출력)
    - ORDER BY 절을 이용하여 추가 정렬 기준 시 그에 따른 순위 부여

## 3. 일반 집계함수

### 가. SUM 함수

- <mark>파티션별 윈도우의 합</mark>
- PARTITION BY 필수 X → 생략 시 전체 행에 대해 집계

```plsql
SELECT TEAM_NAME, PLAYER_NAME, HEIGHT, SUM(HEIGHT) OVER (
            PARTITION BY TEAM_NAME ORDER BY HEIGHT DESC 
            RANGE UNBOUNDED PRECEDING) AS H_SUM
FROM 선수;
```

`RANGE UNBOUNDED PRECEDING`:

- RANGE: 값의 범위
- UNBOUNDED PRECENDING: 가장 처음부터 현재 행까지 범위

  →  누적 합계 등에 쓰임

  → 동일 값 정렬의 경우 동일 값을 모두 포함한 누적 값 표시

</div>

### 나. MAX 함수

- 파티션별 윈도우 최댓값
- 인라인 뷰를 이용하여 최댓값을 가진 행만 추출 가능 → 성능이 떨어짐

  → 순위함수를 이용한 인라인 뷰가 적절

    ```plsql
    SELECT PLAYER_NAME, TEAM_NAME, HEIGHT
    FROM (SELECT PLAYER_NAME, TEAM_NAME, HEIGHT,
                RANK() OVER(PARTITION BY TEAM_NAME
                             ORDER BY HEIGHT DESC) AS H_RANK
        FROM 선수)
    WHERE H_RANK = 1;
    ```

### 다. MIN 함수

- 파티션별 윈도우의 최솟값

### 라. AVG 함수

- 파티션별 윈도우의 평균값
- ROWS 윈도우 함수를 이용하여 원하는 조건의 통계값 구함

```plsql
SELECT TEAM_NAME, PLAYER_NAME, HEIGHT,
        ROUND(AVG(HEIGHT) OVER (PARTITION BY TEAM_NAME
                                ORDER BY PLAYER_NAME
                                ROWS BETWEEN 1 PRECEDING 
                                AND 1 FOLLOWING),2)
                                AS "앞뒤 평균"
FROM 선수;											
```

- 파티션 내 첫번째 행인 나리타의 경우, 자신과 그 다음 행만의 평균

### 마. COUNT 함수

- 파티션별 ROWS 윈도우를 이용하여 원하는 조건의 통계값 구함

```plsql
SELECT PLAYER_NAME, TEAM_NAME, HEIGHT,
				COUNT (*) OVER (PARTITION BY TEAM_NAME 
                                ORDER BY HEIGHT 
                                RANGE BETWEEN 5 PRECEDING AND 
                                            5 FOLLOWING)
                       AS "-5부터 +5까지"
FROM 선수;
```

## 4. 그룹 내 행 순서 함수

### 가. FIRST_VALUE 함수

- 파티션별 윈도우에서 가장 먼저 나온 값 → MIN함수로 대체 가능
- SQL Server 지원X
- 공동 등수 인정X → 추가 ORDER BY 조건 이용

```plsql
SELECT PLAYER_NAME, TEAM_NAME, HEIGHT,
        FIRST_VALUE (PLAYER_NAME) OVER (PARTITION BY TEAM_NAME
                                        ORDER BY HEIGHT DESC) AS 최장신
FROM 선수;												
```

![image.png](/assets/images/posts_img/sql/sql-advanced/sql-33.png)

### 나. LAST_VALUE 함수

- 파티션별 윈도우에서 가장 나중에 나온 값 → MAX로 대체 가능
- SQL Server 지원X
- 공동 등수 인정X → 추가 ORDER BY 조건 이용

### 다. LAG 함수

- 파티션별 윈도우에서 이전 몇 번째 행의 값을 가져옴
- SQL Server 지원X
- 세 개의 인자까지 사용가능 `(가져올 값, 몇 행전(기본 1), NULL 대체 값)`

```plsql
SELECT PLAYER_NAME, TEAM_NAME, HEIGHT, 
        LAG (HEIGHT, 2, 0) OVER (PARTITION BY TEAM_NAME
                                    ORDER BY HEIGHT DESC)
                                    AS "다다음으로 큰 키"
FROM 선수;
```

- 파티션별 윈도우에서 이후 몇 번째 행의 값을 가져옴
- SQL Server 지원X
- 세 개의 인자까지 사용가능 `(가져올 값, 몇 행후(기본 1), NULL 대체 값)`

## 5. 그룹 내 비율 함수

### 가. RATIO_TO_REPORT 함수

- 파티션 내 전체 SUM(칼럼) 값에 대한 행별 칼럼 값의 백분율
- 0~1의 범위
- 개별 RATIO의 합 = 1
- SQL Server 지원X

```plsql
RATION_TO_REPORT (SAL) OVER()
```

### 나. PERCENT_RANK 함수

- 파티션별 윈도우에서 제일 먼저 나오는 것을 0, 가장 나중에 나오는 것을 1로하여 행의 순서별 백분율
    - 첫번째 행 0, 두번째 행 0.5, 세번째 행 1 → 파티션 내 구간 위치 출력
    - 정렬값이 동일한 경우에 대해서는 같은 값
    - <mark>ORDER BY 필수</mark>
- 0~1의 범위
- SQL Server 지원X

```plsql
PERCENT_RANK() OVER (ORDER BY ~)
```

### 다. CUME_DIST 함수

- 파티션별 윈도우의 전체 건수에서 현재 행보다 작거나 같은 건수에 대한 누적 백분율
    - 간격 위치 출력(첫번째 행 0.33, 두번째 행 0.67, 세번째 행 1)
    - 정렬값이 동일한 경우에 대해서는 같은 값(<mark>대신 뒤의 행 기준, 앞 두개가 같으면 둘다 0.67</mark>)
    - <mark>ORDER BY 필수</mark>
- 0~1의 범위
- SQL Server 지원X

```plsql
CUME_DIST () OVER (ORDER BY ~)
```

### 라. NTILE 함수

- 파티션별 전체 건수를 인수 값으로 N등분한 결과
- <mark>ORDER BY 필수</mark>

```plsql
NTLE(3) OVER (ORDER BY SAL)
```

→ 전체 행(14)을 4개로 나눔. → 14/4=3…2, → 나머지는 앞 두 행에 먼저 할당 → 4,4,3,3으로 나눔
