## 0. 서브쿼리(Subquery)

- 하나의 SQL 문안에 포함돼 있는 또 다른 SQL문
- 메인 쿼리가 서브 쿼리를 포함 → 종속 관계
- <mark>서브 쿼리는 메인 쿼리의 칼럼을 모두 사용할 수 있지만, 그 반대는 불가</mark>

  → 서브 쿼리 칼럼을 사용하고 싶으면 조인, 함수, 스칼라 서브 쿼리 사용

- <mark>서브 쿼리는 서브 쿼리의 레벨과는 무관하게 항상 메인 쿼리 레벨로 결과 집합 생성</mark>
    - 조인은 1:1 → 1레벨, 1:M → M레벨, M:N → MN레벨
- 서브 쿼리 사용 시 주의사항
    1. 서브 쿼리는 괄호로 감싸서 기술
    2. 서브 쿼리는 단일 행 또는 다중 행 비교 연산자와 함께 사용 가능
        - 단일 행 비교 연산자는 서브 쿼리 결과가 반드시 1건 이하
        - 다중 행 비교 연산자는 서브 쿼리 결과 건수와 상관 없음
    3. <mark>중첩 서브 쿼리 및 스칼라 서브 쿼리에서는 ORDER BY 사용 못함</mark>
- <mark>동작 하는 방식에 따른 서브 쿼리 분류</mark>
    - **Un-Correlated Subquery(비연관 서브쿼리)**
        - 서브 쿼리가 메인 쿼리의 칼럼을 가지고 있지 않음
        - 메인 쿼리에 값을 제공하기 위한 목적으로 주로 사용
    - **Correlated Subquery(연관 서브 쿼리)**
        - 서브 쿼리가 메인 쿼리 칼럼을 가지고 있음
        - 메인 쿼리가 먼저 수행돼 읽혀진 데이터가 조건이 맞는지 확인하고자 할 때 주로 사용
- <mark>반환되는 데이터 형태에 따른 서브 쿼리 분류</mark>
    - **Single Row Subquery(단일 행 서브 쿼리)**
        - 서브 쿼리의 실행 결과가 항상 1건 이하인 서브 쿼리
        - 댠일 행 비교 연산자(=, <, > 등)와 함께 사용
    - **Multi Row Subquery(다중 행 서브 쿼리)**
        - 서브 쿼리 실행 결과가 여러 건인 서브 쿼리
        - 다중 행 비교 연산자(IN, ALL, ANY, SOME, EXISTS)와 함께 사용
    - **Multi Column Subquery(다중 칼럼 서브 쿼리)**
        - 서브 쿼리의 실행 결과로 여러 칼럼을 반환
        - 메인 쿼리의 조건절에서 여러 칼럼을 동시에 비교 가능
        - 서브 쿼리와 메인 쿼리에서 비교하고자 하는 칼럼 개수와 칼럼의 위치가 동일해야 함

## 1. 단일 행 서브 쿼리(Single Row Subquery)

- 단일 행 비교 연산자와 함께 사용 → <mark>반드시 결과 건수 1건 이하</mark>
    - 2건 이상일 경우 → Run Time 오류 발생

```plsql
SELECT *
FROM 호정대
WHERE DEPARTMENT = (SELECT DEPARTMENT
                    FROM 호정대
                    WHERE SINIGAMI_NAME = '켄파치')
ORDER BY SINIGAMI_NAME;
```

## 2. 다중 행 서브 쿼리(Multi Row Subquery)

- 서브 쿼리 결과가 2건 이상 반환 가능 → <mark>반드시 다중 행 비교 연산자와 함께 사용</mark>
- **다중 행 비교 연산자**

| IN(서브쿼리)           | 서브 쿼리의 결과에 존재하는 임의의 값과 동일한 조건(Multiple OR 조건)                                                      |
|--------------------|----------------------------------------------------------------------------------------------------|
| 비교연산자<br>ALL(서브쿼리) | 서브 쿼리의 결과에 존재하는 모든 값을 만족하는 조건<br>ex. > 사용 시, 서브 쿼리 결과의 최댓값보다 큰 모든 건이 조건 만족                         |
| 비교연산자<br>ANY(서브쿼리) | 서브 쿼리의 결과에 존재하는 어느 하나의 값이라도 만족하는 조건<br>ex. > 사용 시, 서브 쿼리 결과의 최솟값보다 큰 모든 건이 조건 만족 <br>SOME은 ANY와 동일 |
| EXISTS(서브쿼리)       | 서브 쿼리의 결과를 만족하는 값이 존재하는지 여부를 확인하는 조건<br>1건만 찾으면 더 이상 검색X                                           |

```plsql
SELECT *
FROM 선수
WHERE TEAM_NAME IN (SELECT TEAM_NAME
                    FROM 배구팀
                    WHERE REGION = '미야기');
```

## 3. 다중 칼럼 서브 쿼리(Multi Column Subquery)

- 서브 쿼리의 결과로 여러 개의 칼럼이 반환되어 메인 쿼리의 조건과 동시에 비교

## 4. 연관 서브 쿼리(Correlated Subquery)

- 서브 쿼리 내에 메인 쿼리 칼럼 사용 (WHERE절/HAVING 에서 메인쿼리 컬럼을 참조)

  → 각 행마다 다른 조건으로 실행 → <mark>행만큼 서브쿼리 실행</mark> → 성능 부담↑

    - 비연관 서브쿼리는 한 번만 실행됨
- <mark>EXISTS 서브 쿼리는 항상 연관 서브 쿼리</mark>
    - 행 존재 여부만 확인 → 서브 쿼리를 SELECT 1으로 사용 많이 함(1도 표현식이기 때문에 가능)

      → 서브 쿼리의 결과 집합 반환할 필요 없이 하나가 확인되면 종료


```plsql
SELECT *
FROM 배구팀 A
WHERE EXISTS (SELECT 1
                FROM 선수 B
                WHERE A.TEAM_NAME = B.TEAM_NAME);
```

## 5. 그 밖의 위치에서 사용하는 서브 쿼리

### 가. SELECT 절에 서브 쿼리 사용하기

- **스칼라 서브 쿼리(Scalar Subquery)**
    - 한 행, 한 칼럼(1 Row 1 Column)만을 반환하는 서브 쿼리(단일 행 서브 쿼리)
    - 칼럼을 사용하는 대부분의 위치에 사용 가능
    - 메인 쿼리의 결과 건수 만큼 반복 수행됨


```plsql
SELECT A.SINIGAMI_NAME, A.HEIGHT,
			(SELECT AVG(HEIGHT)
			FROM 호정대 B
			WHERE A.DEPARTMENT = B.DEPARTMENT) 평균키
FROM 호정대 A;
```

### 나. FROM 절에서 서브 쿼리 사용하기

- **인라인 뷰(Inline View)**
    - <mark>FROM 절에서 사용되는 서브쿼리</mark>
    - 서브 쿼리 결과를 테이블처럼 사용 가능(쿼리 내에서 즉시 처리, 객체로 저장X)
    - ORDER BY 사용 가능
        - TOP-N쿼리: 인라인 뷰에서 먼저 정렬을 수행하고 정렬된 결과 중 데이터 추출

SELECT A.TEAM_NAME, A.PLAYER_NAME, B.REGION
FROM 선수 A, (SELECT *
            FROM 배구팀
            WHERE REGION != '간사이') B
WHERE A.TEAM_NAME = B.TEAM_NAME;

## 6. 뷰 (View)

- 테이블과 달리 실제 데이터를 가지고 있지 않음
- <mark>뷰 정의(View Definition)민 가지고 있음</mark>
- 질의에서 뷰가 사용되면 뷰 정의를 참조하여 DBMS 내부적으로 질의를 재작성(Rewrite)하여 질의 수행
- 뷰 사용 장점
    - 독립성: 테이블 구조가 변경돼도 뷰를 사용하는 응용 프로그램 변경 필요 없음
    - 편리성: 복잡한 질의를 뷰로 생성함에 따라 관련 질의 단순화, 자주 사용하는 SQL문 이용 시 편리
    - 보안성: 숨기고 싶은 칼럼은 빼고 뷰를 생성하여 사용자에게 정보 감춤
- **뷰 생성(CREATE VIEW)**
    - 이미 생성한 뷰를 기반으로 다시 생성 가능 → 성능상 문제를 고려하여 사용

<div class="col-2-container align-center" markdown="1">
<div class="col-2-item" markdown="1">

```plsql
CREATE VIEW V_선수팀 AS
SELECT A.PLAYER_NAME, A.TEAM_NAME, B.REGION
FROM 선수 A, 배구팀 B
WHERE A.TEAM_NAME = B.TEAM_NAME;
```
