## 1. FROM 절 조인 형태

- 전통적인 방식의 조인 문법 → WHERE 절 조인 조건
- ANSI/ISO SQL 규정 조인 문법 → FROM 절에 명시적으로 정의
    - INNER JOIN
    - NATURAL (INNER) JOIN
    - ON 조건절
    - USING 조건절
    - CROSS JOIN
    - OUTER JOIN

---

## 2. INNER JOIN (내부 조인)

- JOIN의 DEFAULT 옵션, 생략 가능
- 조인 조건을 만족하는 행만 반환
- CROSS JOIN, OUTER JOIN과 함께 사용 불가
- <mark>WHERE 절 조인 조건 → FROM 절 정의 → USING 조건절/ON 조건절 必</mark>
- 애스터리스크(*) 사용 시,  첫 번째 테이블, 두 번째 테이블 순서대로 데이터 출력(기준 칼럼 별개로 출력)

<div class="col-2-container align-center" markdown="1">
<div class="col-2-item" markdown="1">

```sql
--WHERE절 조인 조건
SELECT A.PLAYER_NAME, B.REGION
FROM 선수 A, 배구팀 B
WHERE A.TEAM_NAME  = B.TEAM_NAME
ORDER BY A.TEAM_NAME;
```

</div>
<div class="col-2-item" markdown="1">

```sql
--FROM절 조인 조건
SELECT A.PLAYER_NAME, B.REGION
FROM 선수 A JOIN 배구팀 B
    ON B.TEAM_NAME = A.TEAM_NAME
ORDER BY A.TEAM_NAME;
``` 

</div>
</div>

## 3. NATURAL (INNER) JOIN

- INNER JOIN의 하위 개념으로 해석 가능
- 두 테이블 간, 동일한 이름을 갖는 모든 칼럼들에 대해 EQUI JOIN 수행
- <mark>조인이 되는 테이블의 데이터 도메인과 칼럼명이 동일해야 함(제약조건)</mark>
- <mark>NATURAL JOIN 명시 → USING 조건절, ON 조건절, WHERE 절 조인 조건 정의 불가</mark>
- 애스터리스크(*) 사용 시, 조인 기준 칼럼이 먼저 출력(하나로 출력)
- <mark>조인에 사용된 칼럼은 ALIAS나 테이블 명 접두사 사용 불가</mark>
- SQL Server 지원X

<div class="col-2-container align-center" markdown="1">
<div class="col-2-item" markdown="1">

```plsql
SELECT A.PLAYER_NAME, B.REGION, TEAM_NAME
FROM 선수 A NATURAL JOIN 배구팀 B
WHERE A.PLAYER_NAME != '카게야마'
ORDER BY TEAM_NAME;
```

</div>
<div class="col-2-item" markdown="1">

- 기준 칼럼(TEAM_NAME)이 하나로 합쳐졌기 때문에 A.TEAM_NAME로는 식별 불가

  → 칼럼명만을 이용

- 조인 조건이 아닌 필터 조건 WHERE는 사용 가능

</div>
</div>

## 4. USING 조건절

- 같은 이름을 가진 칼럼들 중에서 <mark>원하는 칼럼에 대해서만 선택적으로 EQUI JOIN</mark>
- 애스터리스크(*) 사용 시, 조인 기준 칼럼이 먼저 출력(하나로 출력), 조인 참여X 칼럼은 별도로 출력
- <mark>조인에 사용된 칼럼은 ALIAS나 테이블 명 접두사 사용 불가</mark>
- <mark>괄호 필수, 여러 칼럼 → 쉼표로 구분 (컬럼1, 컬럼2)</mark>
- SQL Server 지원X

```plsql
SELECT A.PLAYER_NAME, B.REGION
FROM 선수 A JOIN 배구팀 B
USING (TEAM_NAME)
ORDER BY TEAM_NAME;
```

## 5. ON 조건절

- JOIN 조건과 데이터 제한 조건을 분리하여 기술

  → 조인 서술부(ON 조건절)과 비 조인 서술부(WHERE 조건절)

- NATURAL JOIN과 달리 명시적으로 JOIN 조건 구분 가능
- NATURAL JOIN, USING 조건절과 달리 <mark>칼럼명이 달라도 JOIN 조건 가능</mark> → 유연하게 사용가능
- FROM 절에 테이블이 많을 경우 가독성이 떨어짐
- 괄호는 옵션 사항
- <mark>이름이 같은 칼럼에 대해 ALIAS나 테이블 명과 같은 접두사 필수</mark>

### 가. WHERE 절과의 혼용

<div class="col-2-container align-center" markdown="1">
<div class="col-2-item" markdown="1">

```plsql
SELECT A.PLAYER_NAME, B.REGION
FROM 선수 A JOIN 배구팀 B
    ON B.TEAM_NAME = A.TEAM_NAME
WHERE A.TEAM_NAME != '카라스노'
ORDER BY A.TEAM_NAME;
```

</div>
<div class="col-2-item" markdown="1">

![image.png](/assets/images/posts_img/sql/sql-basic/sql-68.png)

</div>
</div>


### 나. ON 조건절 + 데이터 검증 조건 추가

- ON 조건절에 조인 조건 외에 데이터 검색 조건 추가가 가능하지만, WHERE절 기술 권고
    - ex. `ON A.ENAME = B.ENAME AND A.MGR = 3000`

      → `ON A.ENAME = B.ENAME WHERE A.MGR = 3000`

    - OUTER JOIN에서 조인 대상 제한을 위한 추가 조건은 ON 조건절에 기술

### 다. ON 조건절 예제

- 칼럼명이 달라 USING 조건절을 사용할 수 없는 경우

### 라. 다중 테이블 조인

- ON 조건절과 JOIN을 연속으로 작성

<div class="col-2-container align-center" markdown="1">
<div class="col-2-item" markdown="1">

```plsql
-- FROM 조건절로 작성
SELECT A.PLAYER_NAME, B.TEAM_NAME, C.FAMOUS
FROM 선수 A JOIN 배구팀 B
    ON A.TEAM_NAME = B.TEAM_NAME
        JOIN 지역 C
    ON B.REGION = C.REGION;
```

```plsql
-- WHERE 조건절로 작성
SELECT A.PLAYER_NAME, B.TEAM_NAME, C.FAMOUS
FROM 선수 A, 배구팀 B, 지역 C
WHERE A.TEAM_NAME = B.TEAM_NAME
    AND B.REGION = C.REGION;
```

## 6. CROSS JOIN

- E.F.CODD 박사가 언급한 일반 집합 연산자의 PRODUCT(곱집합) 개념
- 조인 조건이 없는 경위 생길 수 있는 모든 데이터의 조합
    - WHERE 조건절로 조인 조건을 추가할 수 있지만, CROSS JOIN 의미가 없어짐
- <mark>M*N건의 데이터 조합 발생</mark>
- 데이터 웨어하우스의 개별 차원을 FACT칼럼과 조인하기 전에 <mark>모든 차원의 곱집합</mark>을 구할 때 유용

<div class="col-2-container align-center" markdown="1">
<div class="col-2-item" markdown="1">

```plsql
SELECT A.PLAYER_NAME, B.REGION
FROM 선수 A CROSS JOIN 배구팀 B
ORDER BY A.PLAYER_NAME;
```

- 선수 테이블 행(11) * 배구팀 테이블 행(4) =44

## 7. OUTER JOIN

- (+)를 이용한 OUTER JOIN의 불편함 개선
- USING 조건절/ON 조건절 필수

### 가. LEFT OUTER JOIN

- 좌측 테이블을 기준으로 우측 테이블의 데이터를 가져오되, <mark>조인 조건 불만족 시, NULL값으로 채움</mark>
- OUTER 키워드 생략 가능

<div class="col-2-container align-center" markdown="1">
<div class="col-2-item" markdown="1">

```plsql
SELECT *
FROM 선수 A LEFT JOIN 배구팀 B
    USING (TEAM_NAME);
```

- 기준 칼럼 맨 앞 위치
- 팀명이 없는 보쿠토 행이 NULL로 채워짐

</div>
<div class="col-2-item" markdown="1">

![image.png](/assets/images/posts_img/sql/sql-basic/sql-71.png)

</div>
</div>


### 나. RIGHT OUTER JOIN

- <mark>우측 테이블을 기준으로 결과 생성</mark>
- OUTER 키워드 생략 가능

<div class="col-2-container align-center" markdown="1">
<div class="col-2-item" markdown="1">

```plsql
SELECT *
FROM 선수 A RIGHT JOIN 배구팀 B
    USING (TEAM_NAME);
```

- 기준 칼럼 맨 앞 위치
- 시라토리자와에 속하는 선수가 없기 때문에 NULL로 채워짐

</div>
<div class="col-2-item" markdown="1">

![image.png](/assets/images/posts_img/sql/sql-basic/sql-72.png)

</div>
</div>


### 다. FULL OUTER JOIN

- 좌측, 우측 테이블의 모든 데이터를 읽어서 조인
- <mark>RIGHT JOIN과 LEFT JOIN의 합집합 → 조인에 성공한 행은 한 번만 표시</mark>
- OUTER 키워드 생략 가능

<div class="col-2-container align-center" markdown="1">
<div class="col-2-item" markdown="1">

```plsql
SELECT *
FROM 선수 A FULL JOIN 배구팀 B
    USING (TEAM_NAME); 
```
