## 1. 데이터베이스

### 가. 데이터베이스의 의미

- 넓은 의미: 일상적인 정보를 모아둔 것
- 좁은 의미: 특정 기업이나 조직, 개인이 필요에 따라 데이터를 일정한 형태로 저장해 놓은 것

  → 일반적 의미의 데이터베이스

  → 데이터의 효율적인 관리와 손상 방지를 위한 소프트웨어 ⇒ `DBMS(Database Management System)`


### 나. 데이터베이스의 발전

- 1960년대: 플로우차트 중심의 개발 방법, 파일 구조로 데이터를 저장·관리
- 1970년대: 계층형·망형(Network) 데이터베이스 상용화
- 1980년대: 현재 사용되는 관계형 데이터베이스 상용화(Oracle, Sybase, DB2)
- 1990년대: 더 향상된 기능, 객체 관계형 데이터베이스(Object Relational)로 발전

### 다. 관계형 데이터베이스(Relational Database)

- E.F. Codd 박사의 논문에서 처음 소개 → IBM의 SQL 개발 → Oracle 발표 → 상용화
- 현재는 객체 지원 기능이 추가된 객체 관계형 데이터베이스 사용
- 핵심 데이터는 대부분 관계형 데이터베이스 구조로 저장
- <mark>파일 시스템은 분산된 데이터 간 정합성 유지 어려움 → 관계형 데이터베이스는 테이블 모델링을 통해 이상(ANOMALY)현상 제거 및 데이터 중복X, 동시성 관리, 병행 제어</mark>

  → 많은 사용자 동시 사용
- 관계형 데이터베이스는 메타 데이터의 총괄 관리를 통해 데이터를 체계화하고, 데이터 표준화를 통한 데이터 품질을 확보함
- DBMS는 <mark>보안 기능(인증된 사용자만 참여)제공 및 데이터무결성(Integrity) 보장, 갑작스러운 장애 대응, 데이터 복구 기능 제공</mark>

## 2. SQL(Structured Query Language)

- <mark>SQL은 관계형 데이터베이스에서 데이터 정의, 데이터 조작, 데이터 제어를 위해 사용하는 언어</mark>

  → 하나의 개발언어, 관계형 데이터베이스에 대한 전담 접속 용도

- 대부분의 관계형 데이터베이스에서 ANSI/ISO 표준(1986년 최초 표준화, 2003년 기준)을 따름
- SQL은 데이터를 집합으로 취급 → 조건에 따른 요구 집합 추출

## 3. STANDARD SQL 개요

- ANSI/ISO 표준 SQL 기능 → SQL 튜닝 효과
    - STANDARD JOIN 기능 추가(CROSS, OUTER JOIN 등)
    - SCALAR SUBQUERY, TOP·N QUERY 등의 새로운 서브 쿼리 기능
    - ROLLUP, CUBE, GROUPING SETS 등의 새로운 리포팅 기능
    - WINDOW FUNCTION과 같은 새로운 개념의 분석 기능

### 가. 일반 집합 연산자

- E.F.Codd 박사의 논문에 언급된 8가지 관계형 대수 중 <mark>일반집합 연산자</mark>

1. `합집합(Union)`
    - `UNION`으로 구현
    - 교집합 제거를 위해 정렬 필요 → 차이가 없다면 중복을 보여주는 `UNION ALL` 사용
2. `교집합(Intersection)`
    - `INTERSECT`로 구현
    - 공통 집합 추출
3. `차집합(Difference)`
    - `EXCEPT`로 구현(Oracle은 `MINUS` )
4. `곱집합(Product)`
    - `CROSS JOIN` 으로 구현→ CROSS PRODUCT(CARTESIAN PRODUCT)
    - JOIN 조건이 없는 경우 생길 수 있는 모든 데이터의 조합 → <mark>M*N 건 발생</mark>

### 나. 순수 관계 연산자

- E.F.Codd 박사의 논문에 언급된 8가지 관계형 대수 중 <mark>순수 관계 연산자로 관계형 데이터베이스를 구현하기 위해 새롭게 만들어진 연산자</mark>

1. `SELECT 연산`
    - WHERE 절로 구현
2. `PROJECT 연산`
    - SELECT 절(SELECT 연산X)의 칼럼 선택 기능으로 구현
3. `(NATURAL) JOIN 연산`
    - WHERE 절의 INNER JOIN 조건절로 구현
    - FROM 절의 NATURAL JOIN, INNER JOIN, OUTER JOIN, USING 조건절, ON 조건절로 구현
4. `DIVIDE`
    - 집합을 XY로 나눴을 때, XY를 모두 가진 A가 답이 되는 기능
    - 현재 사용X

## 4. 테이블(TABLE)

- 데이터를 저장하는 `객체(Object)`
- 데이터는 관계형 데이터베이스의 기본 단위인 테이블 형태로 저장
- 특정한 주제와 목적으로 만들어지는 집합
- <mark>반드시 하나 이상의 칼럼을 가짐</mark>
- 분할된 테이블은 그 칼럼의 값에 의해 연결
    - 정규화를 통해 분할 → 데이터의 정합성 확보 및 이상현상 방지

## 5. ERD(Entity Relationship Diagram)

- E-R 다이어그램: 테이블 간 서로의 상관관계를 그림으로 도식화한 것
- <mark>ERD 구성요소</mark>: `엔터티`, `관계`, `속성` → 현실세계의 데이터 모두 표현 가능
- IE(Information Engineering)표기법, Barker 표기법

## 6. 데이터 유형

- 데이터 유형: 테이블에 특정 자료를 입력할 때, 그 자료를 받아들일 공간을 자료의 유형별로 나누는 기준

  → 선언한 데이터 유형 → 자료 유형 규정(다른 유형 오류 발생)

- 벤더(vendor, 공급자)별로 다름
    - <mark>Oracle은 한 가지의 숫자 데이터 유형 제공</mark>(`NUMBER`)
